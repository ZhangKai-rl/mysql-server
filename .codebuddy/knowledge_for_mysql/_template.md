## 理论基础

> **本章是文档价值的核心，必填。** 它回答"为什么这么设计"，而不是"代码怎么写的"。
> 一篇只有实现细节没有本章的文档，读者只能照着代码复述，无法迁移理解。
>
> 四个小节按需取舍，但**「设计思想与权衡」必写**。

### 设计思想与权衡

这个机制**要解决什么问题**，为什么选了当前这条路，**放弃了哪些方案**、代价是什么。用到的经典设计模式（vtable 抽象、模板方法、迭代器…）也在这里说明其在代码中的体现。

> 写法要求：
>
> 1. 给出至少一个"本来可以那样做，但没有"的对比。
>    例：执行器用火山模型（一次一行）而非向量化（一次一批）——因为 InnoDB 是行式存储，
>    一行是一个完整 record，没有列块可供 SIMD 批处理；代价是每行一次虚函数调用。
> 2. **代价要落到具体后果**：设计里的简化假设会带来什么失效场景、什么阈值下会退化，
>    在这里连着讲——它们是权衡的另一半，不要和产生它们的决策分开。
>    例：ROR-intersection 的选择率乘数假设不同列独立（`ror_scan_selectivity` 注释明写
>    "considered independent"，且无 correlation 检测）⇒ 列强相关时行数严重低估 ⇒ 错选
>    index merge；`eq_range_index_dive_limit` 只缓解 index dive，不缓解 SEL_ARG 树构造。

### 理论溯源

支撑该设计的论文 / 经典算法，以及**源码哪一处体现了它**。

> 只列书名没有意义，要指出落点。
> 例：`RowIterator` 的 `Init()`/`Read()` 契约直接来自 Graefe《Volcano》(1990)；
> hypergraph 的 `EnumerateAllConnectedPartitions` 实现 DPhyp（Moerkotte & Neumann, CIDR 2021）。

### 算法与数据结构

核心算法和数据结构，**为什么选它们**，复杂度。

### 他库对比与演进动机

其他数据库（PostgreSQL / Oracle / ClickHouse / MariaDB…）同类机制怎么做，与 MySQL 的差异及原因；以及本机制**为什么演进成今天这样**。

> 与「概述·版本演进」的分工：那里记**变了什么**（清单），这里记**为什么变**（决策与权衡）。
> 别家分支的私有特性只在此处提及，并明确标注归属。

## 核心实现

> 本章是正文主体，**占篇幅的大头**。组织顺序建议：先给主链路让读者有骨架，再逐个讲关键环节，难点展开讲透。

### 主链路

从入口到底层的流程，让读者先有骨架，知道各环节的先后与职责：

```
handler::ha_commit_trans
  → MYSQL_BIN_LOG::ordered_commit
    → process_flush_stage_queue      写 binlog cache 到文件
      → binlog_cache_data::flush
```

> 必填。这是理解本机制的主线；分支路径在下面各节里讲。函数名是**指称用的术语**，不必标文件与行号。

### XXX（关键环节）

**贴关键代码 + 逐段解释算法逻辑**——这是深度剖析的主要手段，只给结论等于没写透。

```cpp
while (last_rowid_count < m_children.size()) {
  cmp = cmp_ref(child_rowid, m_last_rowid);
  if (cmp < 0) { child->UnlockRow(); continue; }   // 落后候选 → 追赶
  if (cmp > 0) { /* 换新候选，计数重置 */ }
  else last_rowid_count++;                          // 该分支确认了候选
}
```

然后逐段说清：**这段在做什么、为什么必须这么做、边界情况怎么处理**。

> 写法要求：
>
> - **代码要贴，但要节选**：只留讲解需要的骨架，无关分支用 `...`
> - **每段代码后面必须有算法解释**，光贴不解释等于没写
> - 难点的判据是**能解释"为什么不得不这样"**，而不只是"它是这样"
> - 反直觉处、隐含假设、复杂状态机要重点展开
> - 如果结论能用 EXPLAIN / EXPLAIN ANALYZE / optimizer trace 的输出印证，就地贴出来对照——
>   这比单纯讲代码更有说服力（例：trace 的 `cumulated_total_cost` 就是 `ror_intersect_add` 累加出来的值）
